# RRULE (recurrence rule) - RFC 5545 subset for Tasklog

**Researched:** 2026-05-27
**Source:** RFC 5545 (iCalendar), Section 3.3.10 "Recurrence Rule" - https://www.rfc-editor.org/rfc/rfc5545
**Why:** Tasklog stores recurrence as an RRULE-shaped string so the grammar can grow across versions (v2.14.0 core -> v2.14.1 advanced -> v2.14.2 natural language) without re-shaping the storage. This file pins the canonical grammar so the typed structure stays spec-compatible.

---

## RECUR value-type ABNF (verbatim, trimmed to the parts we use)

```
recur           = recur-rule-part *(";" recur-rule-part)
recur-rule-part = (freq / until / count / interval / byday
                 / bymonthday / bysetpos / ...)
freq            = "FREQ" "=" freq-value
freq-value      = "SECONDLY" / "MINUTELY" / "HOURLY" / "DAILY"
                / "WEEKLY" / "MONTHLY" / "YEARLY"
interval        = "INTERVAL" "=" 1*DIGIT
byday           = "BYDAY" "=" byday-list
byday-list      = wday *("," wday)
wday            = [(["+"] / "-") 1*DIGIT] weekday
weekday         = "SU" / "MO" / "TU" / "WE" / "TH" / "FR" / "SA"
bymonthday      = "BYMONTHDAY" "=" bymonthday-list
bymonthday-element = (["+"] / "-") ordyearday      ; 1..31, or -1..-31 from month end
count           = "COUNT" "=" 1*DIGIT
until           = "UNTIL" "=" enddate
bysetpos        = "BYSETPOS" "=" bysetpos-list
```

### Semantics that matter

- **INTERVAL** - positive integer, default `1`. "the recurrence repeats every occurrence of the frequency specified." So `FREQ=DAILY;INTERVAL=3` = every 3 days.
- **BYDAY** - comma-separated two-letter weekday codes (`SU MO TU WE TH FR SA`). An optional leading signed integer picks the nth weekday-of-month: `3TH` = third Thursday, `-1MO` = last Monday.
- **BYMONTHDAY** - 1..31 (day of month), or negative to count from the end (`-1` = last day).
- **COUNT** / **UNTIL** - end conditions (after N occurrences / on/before a date). Mutually exclusive.
- **BYSETPOS** - selects the nth result from the set the other rules produce (e.g. "3rd weekday of the month").

## Canonical examples

| Pattern | RRULE |
|---|---|
| Every day | `FREQ=DAILY` |
| Every 3 days | `FREQ=DAILY;INTERVAL=3` |
| Every weekday (Mon-Fri) | `FREQ=WEEKLY;BYDAY=MO,TU,WE,TH,FR` |
| Weekly on Mon/Wed/Fri | `FREQ=WEEKLY;BYDAY=MO,WE,FR` |
| Monthly on the 15th | `FREQ=MONTHLY;BYMONTHDAY=15` |
| Monthly on the 3rd Thursday | `FREQ=MONTHLY;BYDAY=3TH` |
| Monthly on the last day | `FREQ=MONTHLY;BYMONTHDAY=-1` |

## What Tasklog implements per version

**v2.14.0 (recurrence core) - this version:**

| Subset | RRULE produced | Next-deadline rule |
|---|---|---|
| Daily | `FREQ=DAILY` | deadline + 1 day |
| Every N days | `FREQ=DAILY;INTERVAL=N` | deadline + N days |
| Weekly on weekday(s) | `FREQ=WEEKLY;BYDAY=...` | next calendar day after the deadline whose weekday is in the set |
| Monthly on day D | `FREQ=MONTHLY;BYMONTHDAY=D` (D in 1..28 safe) | day D of the next month; D > days-in-month clamps to month end |

- **INTERVAL** parsed/honored for `FREQ=DAILY` (every N days). In the v2.14.0 core, weekly/monthly INTERVAL was assumed 1; `INTERVAL>1` for weekly/monthly is implemented in v2.14.1 (see the table below).
- **Time of day is preserved** - the next deadline keeps the original deadline's `TimeOfDay` (v2.12.0 timed-deadline support). A "daily 15:00" repeat stays at 15:00.
- The expander is a **pure function of the current deadline** (advance-from-scheduled-date, Todoist default). It never reads the clock, so it is unaffected by the `DateTime.Now`/`UtcNow` deviation (#18) and is trivially unit-testable.

**v2.14.1 (advanced grammar) - implemented:**

| Form | RRULE | Next-deadline rule |
|---|---|---|
| Nth weekday of month | `FREQ=MONTHLY;BYDAY=3TH` | the Nth (1..4) occurrence of that weekday in the target month |
| Last weekday of month | `FREQ=MONTHLY;BYDAY=-1FR` | the last occurrence of that weekday in the target month |
| Day from month end | `FREQ=MONTHLY;BYMONTHDAY=-1` | `-1` = last day, `-2` = second-to-last, ... (`daysInMonth + 1 + value`) |
| Every N weeks | `FREQ=WEEKLY;INTERVAL=2;BYDAY=MO` | next matching weekday whose week is a multiple of N weeks from the anchor week |
| Every N months | `FREQ=MONTHLY;INTERVAL=2;BYMONTHDAY=1` | the day/nth-weekday N months on |
| Ends on a date | `...;UNTIL=20261231` | spawn only while `next.Date <= UNTIL` |
| Ends after N times | `...;COUNT=5` | spawn only while the series has fewer than N occurrences |

Semantics locked for v2.14.1 (Todoist conventions):

- **Nth weekday:** `BYDAY` with a leading signed ordinal (`3TH`, `-1MO`). Only ONE ordinaled weekday allowed (reject `BYDAY=3TH,1MO`). Ordinals `+1..+4` and `-1` (last); a `+N` that doesn't exist in the target month (e.g. a 5th Friday) clamps to the last occurrence. Algorithm: for `+N`, first day of the target month -> first matching weekday -> `+7*(N-1)` days (clamp into month); for `-1`, last day -> walk back to the weekday.
- **Negative `BYMONTHDAY`:** `-1..-28` supported (so February's `-1` works); more-negative clamps to day 1. Day = `DateTime.DaysInMonth + 1 + value`.
- **`INTERVAL>1`:** weekly anchors weeks to the current deadline's week (Sunday-start, matching `ComputeDueStatus`); a candidate day is valid when its week is `weekDiff % INTERVAL == 0` from the anchor - this unifies single- and multi-weekday with any interval, and reduces to "next matching weekday" at `INTERVAL=1`. Monthly advances `AddMonths(INTERVAL)`.
- **End conditions (no DB column):** `UNTIL` (date) and `COUNT` (integer) live in the rule string. At spawn time (in `Complete`), the next occurrence is created only if `(UNTIL is null || next.Date <= UNTIL)` AND `(COUNT is null || existingSeriesRowCount < COUNT)`. `COUNT` is evaluated by counting rows with the same `SeriesId` (the v2.14.0 history) - completing occurrence #k sees exactly k rows, so it spawns iff `k < COUNT`, yielding exactly `COUNT` occurrences. Caveat: deleting a mid-series occurrence skews the count (acceptable; deletion is rare + destructive). `UNTIL`/`COUNT` are mutually exclusive (RFC); reject both together.
- **`BYSETPOS` is NOT implemented** - `BYDAY=3TH` is the simpler canonical form for every "3rd Thursday"-style case Tasklog supports, so raw `BYSETPOS` is unnecessary and stays rejected.

**Deferred (still rejected):**

- **v2.14.2:** natural-language entry ("every weekday", "every other monday") -> rule (parsing, not new grammar).

**Out of scope entirely (Tasklog has no use):** `SECONDLY/MINUTELY/HOURLY` frequencies, `BYYEARDAY`, `BYWEEKNO`, `BYSETPOS`, `YEARLY` with `BYMONTH`.

## Validation rules the core enforces

- A recurrence rule requires a deadline (the anchor). Reject recurrence on a task with no deadline.
- `FREQ` is required and must be one of `DAILY` / `WEEKLY` / `MONTHLY` for the core.
- `WEEKLY` requires a non-empty `BYDAY`; `MONTHLY` requires a `BYMONTHDAY` in 1..31; `INTERVAL` (if present) must be >= 1.
- Unknown / unsupported parts are rejected by the parser with a 400 so we never silently accept a rule the expander can't advance. (In the v2.14.0 core that included `COUNT`/`UNTIL`/nth-weekday/negative-`BYMONTHDAY`/`INTERVAL>1`; v2.14.1 promotes those to accepted - see the v2.14.1 table above. `BYSETPOS`, `BYWEEKNO`, `BYYEARDAY`, sub-daily frequencies stay rejected.)
